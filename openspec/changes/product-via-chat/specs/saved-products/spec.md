# Spec Delta

## ADDED Requirements

### Requirement: Продукт заводится разбором снимка упаковки

Система ДОЛЖНА позволять завести продукт по снимку упаковки, разобрав таблицу пищевой ценности
моделью (SHALL). Слова человека, присланные вместе со снимком, ДОЛЖНЫ учитываться при разборе
(SHALL).

#### Scenario: Снимок таблицы

- **WHEN** человек присылает снимок упаковки с таблицей пищевой ценности
- **THEN** приложение показывает название продукта и значения КБЖУ, а числа в разборе можно
  поправить до сохранения

#### Scenario: Слова вместе со снимком

- **WHEN** человек присылает снимок и пишет словами, что это за продукт
- **THEN** название берётся с учётом сказанного, а значения остаются из таблицы на снимке

#### Scenario: Таблицы на снимке нет

- **WHEN** на снимке таблица пищевой ценности не читается
- **THEN** приложение показывает оценку значений и говорит, что это оценка, а не таблица

#### Scenario: Таблицу не удалось прочитать

- **WHEN** по снимку нельзя определить значения КБЖУ
- **THEN** модель задаёт один короткий вопрос, а ответ на него продолжает тот же разбор

### Requirement: Значения из разбора упаковки отнесены к 100 г

Система ОБЯЗАНА приводить значения разбора к 100 г, когда на упаковке они отнесены к другой
граммовке (MUST).

#### Scenario: Таблица дана на порцию

- **WHEN** в таблице на упаковке 60 ккал отнесены к порции 30 г
- **THEN** в продукте оказывается 200 ккал на 100 г, и остальные значения пересчитаны так же

#### Scenario: Таблица дана на 100 г

- **WHEN** значения в таблице на упаковке уже отнесены к 100 г
- **THEN** значения переносятся в продукт без пересчёта

### Requirement: Продукт из разбора упаковки идёт в список, а не в дневник

Система ДОЛЖНА сохранять продукт из разбора только по подтверждению человеком (SHALL).
Запись в дневник дня при этом создаваться НЕ ДОЛЖНА (MUST NOT). Снимок упаковки вместе
с продуктом сохраняться НЕ ДОЛЖЕН (MUST NOT).

#### Scenario: Сохранение по подтверждению

- **WHEN** человек подтверждает сохранение разбора упаковки
- **THEN** продукт появляется в списке «Мои продукты»

#### Scenario: Дневник остаётся прежним

- **WHEN** продукт сохранён из разбора упаковки
- **THEN** в ленте дня новых записей не появилось

#### Scenario: Название уже есть в списке

- **WHEN** название из разбора совпадает с сохранённым продуктом
- **THEN** второй продукт не появляется, а значения существующего обновляются

#### Scenario: Снимок не остаётся при продукте

- **WHEN** человек открывает сохранённый продукт позже
- **THEN** снимка упаковки при продукте нет

### Requirement: Разбор упаковки доступен из списка продуктов

Система ДОЛЖНА давать вход в разбор снимка упаковки из списка продуктов (SHALL).

#### Scenario: Вход в разбор

- **WHEN** человек открывает список продуктов
- **THEN** рядом с добавлением продукта виден вход в разбор снимка упаковки

### Requirement: Стоимость разбора упаковки видна

Система ДОЛЖНА показывать стоимость разбора упаковки и учитывать её в журнале расхода (SHALL).

#### Scenario: Стоимость разбора

- **WHEN** разбор упаковки получен
- **THEN** рядом видно, сколько он стоил, и запрос учтён в журнале расхода как анализ фото
