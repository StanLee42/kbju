# KBJU

Личное приложение для учёта КБЖУ: фотографируете еду или надиктовываете голосом, что
съели — модель распознаёт, считает калории, белки, жиры и углеводы, запись попадает
в дневник. Приложение показывает, сколько съедено за день относительно вашей нормы.

Не для масс-маркета, сделано под одного человека и один телефон.

## Особенности

- Ввод без взвешивания: фото еды и/или голос, плюс один тап «мало / средне / много».
- Если точный вес известен — его можно ввести, и он перебьёт оценку модели.
- Дневник, вес, вода и фото тела хранятся только на телефоне.
- Фото тела никогда не отправляются ни в одну модель.
- Голос распознаётся на самом телефоне, аудио в сеть не уходит — в модель уходит уже текст.
- Провайдер — DeepSeek: один ключ на текст, фото и поиск в сети. Слой провайдеров переключаемый.
- Можно прислать отчёт биоимпеданса картинкой или PDF — нормы выводятся из состава тела,
  а не из общей формулы.
- Расписание типов дней (обычный, тренировка) настраивается целиком: своя недельная сетка,
  исключения на даты, ручное переключение на сегодня.

## Как это попадает на телефон

Приложение — это PWA, то есть обычный сайт, который ставится на рабочий стол как
приложение: открываете ссылку в Chrome на Android, выбираете «Установить приложение»,
и на экране появляется иконка, а приложение открывается на весь экран без адресной строки.

Хостинг — бесплатный, с HTTPS. HTTPS обязателен: без него браузер не даёт доступ
к камере и микрофону. Папка готовится так, чтобы выкладывалось перетаскиванием на Netlify.

Локальная разработка — обычный статический сервер на `localhost`: он считается
защищённым контекстом, поэтому камера и микрофон работают и на компьютере.

## Статус

Работают два этапа. Каркас: экран «Сегодня» с кольцами калорий и БЖУ, полосками остатка,
лентой записей и итогом, ручное добавление и правка, настройки типов дней, расписания
(недельная сетка и вращающийся цикл), исключений на даты и хранилища.

Фото и анализ: снимок тарелки или упаковки уходит в модель, результат показывается карточкой
с правкой чисел и выбором порции, запись сохраняется только по подтверждению. В настройках —
ключ провайдера с проверкой и разбор отчёта биоимпеданса, из которого приложение само считает
нормы. Отдельный экран показывает расход токенов и денег, прогноз на месяц, бюджет и остаток
на счету провайдера. Слой инструментов для будущего ассистента описан и покрыт тестами.

Дальше — третий этап: голосовой ввод с распознаванием речи на устройстве.

## Разработка по спецификациям

Проект ведётся по OpenSpec: сначала спецификация, потом код. Источник истины о поведении —
`openspec/specs/`, где каждое требование записано сценариями WHEN/THEN. Предложения о будущих
изменениях лежат в `openspec/changes/`, завершённые переезжают в `openspec/changes/archive/`
с датой в имени.

| Каталог | Роль |
|---|---|
| `openspec/specs/` | как приложение должно вести себя **сейчас** |
| `openspec/changes/` | что предлагается сделать, ещё не сделано |
| `openspec/changes/archive/` | история завершённых изменений |
| `.misc/` | планы, решения и разборы «почему так» — это не контракт поведения |

Команды:

```
openspec list                      # предложения и их прогресс
openspec list --specs              # возможности и число требований в каждой
openspec show <имя>                # показать предложение или спецификацию
openspec validate --all --strict   # проверить формат спек и предложений
openspec archive <имя> -y          # перенести требования в specs/ и убрать в архив
openspec view                      # интерактивная панель
```

В ZCode добавлены команды и навыки OpenSpec (каталог `.zcode/`): `/opsx:explore`,
`/opsx:propose`, `/opsx:apply`, `/opsx:sync`, `/opsx:archive`. Расширенный набор включается
через `openspec config profile` и затем `openspec update`.

Порядок работы: `/opsx:propose` описывает изменение и его дельта-спеки → задачи в `tasks.md`
отмечаются по ходу реализации → `/opsx:archive` переносит требования в `openspec/specs/`.
Артефакты пишутся по-русски, структурные заголовки и ключевые слова SHALL/MUST остаются
английскими (задано в `openspec/config.yaml`).

Подробная инструкция по подходу, с разбором артефактов, дельт, типичных ошибок и полным
циклом работы — в [`.misc/HOWTO_OPENSPEC.md`](.misc/HOWTO_OPENSPEC.md).

## Разработка

Сборки нет, всё — статические файлы. Открывать через `file://` нельзя: браузер не даёт
загружать ES-модули и работать с хранилищем. Нужен локальный сервер:

```
python3 -m http.server 8765
# открыть http://127.0.0.1:8765
```

`localhost` браузер считает защищённым адресом, поэтому камера и микрофон работают и на
компьютере — это понадобится на следующих этапах.

Проверки:

```
node --test                       # расчёты, разбор ответов, стоимость, порции, инструменты
node tools/make-icons.mjs         # перегенерировать PNG-иконки
```

Сквозные проверки в headless Chrome (нужен запущенный браузер с отладочным портом и ключ
в `.env.local`):

```
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless=new --remote-debugging-port=9222 --user-data-dir=/tmp/kbju-profile about:blank &

node tools/cdp-check.mjs http://127.0.0.1:8765/#/today      # отрисовка и ошибки консоли
node tools/cdp-flow.mjs                                     # запись еды и перезагрузка
node tools/cdp-e2e.mjs                                      # ключ, отчёт, нормы, расход, экран дня
node tools/spike-deepseek.mjs --limit 2                     # прогон снимков через модель
```

Скрипты сами выгружают системные корневые сертификаты macOS: у Node на этой машине пустое
встроенное хранилище, и без этого запросы падают с ошибкой проверки сертификата.

## Публикация на телефон

Публикуется не репозиторий, а собранная папка только с файлами приложения:

```
node tools/build-www.mjs      # соберёт dist/
```

Скрипт копирует ровно `index.html`, `manifest.webmanifest`, `sw.js`, `css/`, `js/` и `icons/`,
проверяет, что service worker не ссылается на отсутствующие файлы, отдельно убеждается,
что в сборку не попали файлы с ключами, и подставляет в service worker имя кэша по отпечатку
содержимого. Последнее важно: без смены имени кэша браузер после публикации продолжал бы
отдавать старую версию приложения. В публикацию не уходят `.env.local`, история git,
`openspec/`, `.misc/`, `spike/`, `tools/` и `tests/`.

Дальше:

1. открыть <https://app.netlify.com/drop> на компьютере;
2. перетащить папку `dist` целиком в окно браузера и дождаться окончания выгрузки (около полуминуты);
3. получить адрес вида `имя-123456.netlify.app` — он уже по HTTPS, а без HTTPS браузер
   не даст доступ к камере и микрофону;
4. нажать `Claim your site` и войти бесплатным аккаунтом, чтобы сайт остался за вами:
   без этого он работает, но управлять им нельзя;
5. переименовать сайт в неугадываемое имя: `Site configuration` → `Change site name`;
6. открыть адрес в Chrome на телефоне и выбрать «Установить приложение» — появится иконка,
   приложение откроется на весь экран без адресной строки;
7. для обновления пересобрать `dist` и перетащить папку снова в тот же сайт.

Бесплатный тариф Netlify даёт около 20 публикаций в месяц — для личного приложения с запасом.

Личные материалы для проверки моделей лежат в `spike/`, который в репозиторий не попадает:
`spike/in/` — фотографии тарелок и отчёты, `spike/out/` — результаты прогонов.
Ключ провайдера хранится в `.env.local`, тоже вне гита.
