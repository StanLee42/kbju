# KBJU

Личное приложение для учёта КБЖУ: пишете словами или прикладываете снимок еды — модель
распознаёт, считает калории, белки, жиры и углеводы, запись попадает в дневник. Приложение
показывает, сколько съедено за день относительно вашей нормы.

Не для масс-маркета, сделано под одного человека и один телефон.

## Особенности

- Ввод без взвешивания: словами, снимком или тем и другим вместе, плюс выбор порции
  «всё / половина» и свои граммы, если точный вес известен.
- Модель может задать один уточняющий вопрос, если без ответа числа не получить.
- Запись уходит в дневник только по подтверждению.
- Нормы обсуждаются разговором: модель меняет рычаги, а числа считает приложение.
- Дневник, вес, вода и фото тела хранятся только на телефоне.
- Фото тела никогда не отправляются ни в одну модель.
- Календарь показывает месяц клетками и съеденное за каждый день; записи дня можно
  объединять в одну и разбирать на составляющие.
- Провайдер — DeepSeek: один ключ на текст и фото. Слой провайдеров переключаемый.
- Можно прислать снимок отчёта биоимпеданса в разговоре о нормах — нормы выводятся
  из состава тела, а не из общей формулы.
- Расписание типов дней (обычный, тренировка) настраивается целиком: своя недельная сетка,
  исключения на даты, ручное переключение на сегодня.

## Как это попадает на телефон

Приложение — это PWA, то есть обычный сайт, который ставится на рабочий стол как
приложение: открываете ссылку в Chrome на Android, выбираете «Установить приложение»,
и на экране появляется иконка, а приложение открывается на весь экран без адресной строки.

Хостинг — бесплатный, с HTTPS. HTTPS обязателен: без него приложение не ставится на
рабочий стол и не работает служба обновления. Публикация идёт сама при пуше в `main`.

Локальная разработка — обычный статический сервер на `localhost`: он считается
защищённым контекстом, поэтому приложение на компьютере работает так же, как на телефоне.

## Статус

Работают четыре этапа.

Каркас: экран дня с полосками калорий и БЖУ, лентой записей и итогом, ручное добавление
и правка, настройки типов дней, расписания (недельная сетка и вращающийся цикл),
исключений на даты и хранилища.

Фото и анализ: снимок тарелки или упаковки уходит в модель, результат показывается карточкой
с правкой чисел и выбором порции, запись сохраняется только по подтверждению. В настройках —
ключ провайдера с проверкой. Отдельный экран показывает расход токенов и денег, прогноз
на месяц, бюджет и остаток на счету провайдера.

Разговор: кнопка «Добавить» в нижней панели открывает окно, куда еду можно написать словами,
приложить снимком или сделать и то и другое, с уточнениями и стоимостью каждого запроса.
Нормы обсуждаются тем же способом: модель меняет рычаги, а числа считает приложение
и показывает расчёт по шагам.

Дни и записи: календарь месяца клетками с суммами за день, переход в прошлый день тем же
экраном, объединение нескольких записей одного приёма в одну и разбор записи на позиции.

Дальше — голосовой ввод с распознаванием речи на устройстве. Работа сделана и проверена,
но живёт в ветке `ai/voice` и в мастер пока не идёт.

## Разработка по спецификациям

Проект ведётся по OpenSpec: сначала спецификация, потом код. Источник истины о поведении —
`openspec/specs/`, где каждое требование записано сценариями WHEN/THEN. Предложения о будущих
изменениях лежат в `openspec/changes/`, завершённые переезжают в `openspec/changes/archive/`
с датой в имени.

| Каталог | Роль |
|---|---|
| `openspec/specs/` | как приложение должно вести себя **сейчас** |
| `openspec/changes/` | что предлагается сделать, ещё не сделано |
| `openspec/changes/archive/` | история завершённых изменений |
| `.misc/` | планы, решения и разборы «почему так» — это не контракт поведения |

Команды:

```
openspec list                      # предложения и их прогресс
openspec list --specs              # возможности и число требований в каждой
openspec show <имя>                # показать предложение или спецификацию
openspec validate --all --strict   # проверить формат спек и предложений
openspec archive <имя> -y          # перенести требования в specs/ и убрать в архив
openspec view                      # интерактивная панель
```

В ZCode добавлены команды и навыки OpenSpec (каталог `.zcode/`): `/opsx:explore`,
`/opsx:propose`, `/opsx:apply`, `/opsx:sync`, `/opsx:archive`. Расширенный набор включается
через `openspec config profile` и затем `openspec update`.

Порядок работы: `/opsx:propose` описывает изменение и его дельта-спеки → задачи в `tasks.md`
отмечаются по ходу реализации → `/opsx:archive` переносит требования в `openspec/specs/`.
Артефакты пишутся по-русски, структурные заголовки и ключевые слова SHALL/MUST остаются
английскими (задано в `openspec/config.yaml`).

Подробная инструкция по подходу, с разбором артефактов, дельт, типичных ошибок и полным
циклом работы — в [`.misc/HOWTO_OPENSPEC.md`](.misc/HOWTO_OPENSPEC.md).

## Разработка

Приложение — статические файлы, сборки для запуска не нужно. Открывать через `file://`
нельзя: браузер не даёт загружать ES-модули и работать с хранилищем. Нужен локальный сервер:

```
python3 -m http.server 8765
# открыть http://127.0.0.1:8765
```

`localhost` браузер считает защищённым адресом, поэтому приложение работает и на компьютере.

Проверки:

```
node --test                       # расчёты, разбор ответов, стоимость, порции, инструменты
node tools/make-icons.mjs         # перегенерировать PNG-иконки
```

Сквозные проверки в headless Chrome (нужен запущенный браузер с отладочным портом и ключ
в `.env.local`):

```
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless=new --remote-debugging-port=9222 --user-data-dir=/tmp/kbju-profile about:blank &

node tools/cdp-check.mjs http://127.0.0.1:8765/#/today      # отрисовка и ошибки консоли
node tools/cdp-flow.mjs                                     # запись еды и перезагрузка
node tools/cdp-e2e.mjs                                      # ключ, отчёт, нормы, расход, экран дня
node tools/cdp-layout.mjs                                   # вёрстка и касания на экранах 320–430px
node tools/cdp-update.mjs                                   # подхват новой сборки после публикации
node tools/spike-deepseek.mjs --limit 2                     # прогон снимков через модель
```

Скрипты сами выгружают системные корневые сертификаты macOS: у Node на этой машине пустое
встроенное хранилище, и без этого запросы падают с ошибкой проверки сертификата.

### Эмулятор Android

Проверять приложение можно на настоящем Chrome для Android, не беря телефон в руки.
Инструменты установлены в `/opt/homebrew/share/android-commandlinetools`, виртуальное
устройство называется `kbju`.

```
emulator -avd kbju &                    # запустить виртуальное устройство (окно откроется)
adb reverse tcp:8765 tcp:8765           # дать эмулятору доступ к локальному серверу
node tools/emu.mjs open http://127.0.0.1:8765/
node tools/emu.mjs shot /tmp/emu.png    # снимок экрана
node tools/emu.mjs ui                   # список надписей на экране с координатами
node tools/emu.mjs tap-text "No thanks" # нажать по надписи
node tools/emu.mjs tap 945 2222         # нажать по координатам

# отладка Chrome внутри эмулятора: те же проверки, что и в headless
adb forward tcp:9223 localabstract:chrome_devtools_remote
CDP_PORT=9223 node tools/cdp-layout.mjs http://127.0.0.1:8765
```

## Публикация на телефон

Публикуется не репозиторий, а собранная папка только с файлами приложения:

```
node tools/build-www.mjs      # соберёт dist/
```

Скрипт копирует ровно `index.html`, `manifest.webmanifest`, `sw.js`, `css/`, `js/` и `icons/`,
проверяет, что service worker не ссылается на отсутствующие файлы, отдельно убеждается,
что в сборку не попали файлы с ключами, подставляет в service worker имя кэша по отпечатку
содержимого и вписывает ту же версию в `js/version.js`. Последнее важно: без смены имени
кэша браузер после публикации продолжал бы отдавать старую версию приложения, а без версии
в самом коде нельзя понять, какая сборка работает прямо сейчас. В публикацию не уходят
`.env.local`, история git, `openspec/`, `.misc/`, `spike/`, `tools/` и `tests/`.

Публикация идёт сама: пуш в `main` запускает `.github/workflows/pages.yml`, а тот прогоняет
тесты, собирает папку и выкладывает её на GitHub Pages.

1. запушить изменения: `git push origin main`;
2. дождаться зелёной сборки в GitHub Actions;
3. открыть <https://stanlee42.github.io/kbju/> в Chrome на телефоне и выбрать
   «Установить приложение» — появится иконка, приложение откроется на весь экран
   без адресной строки;
4. для обновления достаточно запушить новое изменение: приложение подхватит новую сборку само.

Иконку на iPhone ставьте только с адреса GitHub Pages: у старого адреса Netlify иконка
не обновляется никогда. Установка на живом iPhone пока не проверялась.

### Старый способ: Netlify Drop

Собранную папку можно по-прежнему перетащить в <https://app.netlify.com/drop> — так делали
раньше, и это работает. Неудобство в том, что бесплатный тариф считает публикации: 300
кредитов в месяц, одна выгрузка около 15 кредитов, то есть примерно двадцать публикаций.
Адрес Netlify остаётся прежним и сам не обновляется.

## Где ещё можно разместить

| Куда | Публикаций в месяц | Как выкладывать | Что учесть |
|---|---|---|---|
| GitHub Pages | без жёсткого счёта, мягкий лимит около 10 сборок в час | пуш в репозиторий, выкладка сама | то, чем пользуемся сейчас; на бесплатном тарифе только для публичных репозиториев |
| Netlify Drop | около 20 | перетащить папку | старый адрес; публикации считаются |
| Cloudflare Pages | 500 | перетащить папку или zip | проект с прямой загрузкой нельзя потом переключить на Git, придётся пересоздавать |

Настройка для GitHub Pages лежит в репозитории: `.github/workflows/pages.yml`. Установка
зависимостей в нём не нужна — и приложение, и сборка используют только возможности самого
Node. Если Pages отключены: в настройках репозитория → Pages → Source: GitHub Actions.

Рабочий GitLab для личного проекта не подходит: это инфраструктура работодателя.

Личные материалы для проверки моделей лежат в `spike/`, который в репозиторий не попадает:
`spike/in/` — фотографии тарелок и отчёты, `spike/out/` — результаты прогонов.
Ключ провайдера хранится в `.env.local`, тоже вне гита.
